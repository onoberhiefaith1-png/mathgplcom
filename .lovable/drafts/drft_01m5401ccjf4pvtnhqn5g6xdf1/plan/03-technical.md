## Technical details
- **Staged additive migration** (applies when the draft is accepted): `academia_mcq_papers` (academia_id, subject_id, source_notebook_id unique per subject, title, questions jsonb `[{n, text, objects?, options:[{label,text}], answer}]`, order_index), `academia_mcq_attempts` (paper_id, user_id or guest_id, answers jsonb, correct/incorrect/unanswered, score, submitted_at). RLS mirrors existing Academia tables: public-Academia read for papers; owner/assigned-teacher write; attempts own-row only; GRANTs included.
- `src/lib/academia/mcq/parse.ts` — pure parser from note document to questions + issue list; `mark.ts` — pure marking and Correct/Incorrect/Unanswered split (shared by web and offline). Vitest covers: option/answer detection, missing answer flagged, original numbering kept in review, retry never edits a submitted attempt.
- UI: `SubjectCardMenu` (DropdownMenu, `stopPropagation`) added to the existing subject cards in `StudentAcademiaView`, teacher/school Academia subject cards, and `AcademiaScreens` (Mathemagine). New routes `/academia/subject/$subjectId/questions`, `/academia/mcq/$paperId` (exam/results/review via search param). Components under `src/components/academia/mcq/`, light semantic tokens only.
- Convert dialog reached from the lesson-note ⋯ menu; Academia picker reuses existing assigned-subject queries.
- Offline: papers added to `/api/public/academia-pack` (public Academias only), attempts appended to the existing `/api/public/academia-sync` queue.
- Rule recorded in `src/lib/academia/AGENTS.md`: MCQ papers are subject-level and independent of Sessions/Game.
