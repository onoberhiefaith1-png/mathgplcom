## How the test runs

1. Create a fresh lesson note in the workspace (named `Pilot Test — Completing the Square`) so nothing existing is touched.
2. Open it, open the Co-Pilot panel, set the structure numbers above, confirm.
3. Give the topic/subtopic as the additional information, let the Copilot analyse and produce the draft blueprint.
4. Review the draft: check every Example/Exercise/Assignment row shows a real, solvable completing-the-square question, no duplicates, sensible progression.
5. Approve and let it build all 22 items. Watch the narrated per-item progress to the end — confirm nothing truncates part-way.
6. Read the finished note and judge it as a teacher would.

## What gets judged

- Question quality: genuinely completing-the-square (not factorising in disguise), varied coefficients, rising difficulty, no repeats across Example → Exercise → Assignment.
- Solution quality against the classroom standard: one micro-step per line, stacked fractions, the half-of-b-squared step never skipped, the question restated verbatim on line 1.
- Linkage: every question keeps its solution; student-facing rows hide the solution but retain it for Smartboard.
- Rendering: `x²`, `±`, stacked fractions and surds display correctly, no code-style syntax.
- Professional tone: introduction/explanation read as a real lesson, varied wording, no filler.
- Completeness and timing: all 22 items built, no empty section, no dropped tail; note how long the run takes.
