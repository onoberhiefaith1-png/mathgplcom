## How it gets built

### Stage 1 — Aura can see and hold a real game
Point Aura's game abilities at the real Slate Game records instead of the old table, and
give her: list games, open one and read its full saved settings, create a draft, set its
title/topic/instructions/room, attach and reorder lesson-note questions, and read back
what saved. Every one of these reuses the existing save/load code, so a game Aura makes
opens normally in your editor and behaves identically in play.

A "what can you actually do" ability is added too: Aura can list her own abilities and
say plainly which parts are built, which are testable, and which do not exist.

### Stage 2 — Lesson-note authoring completed
Fill the remaining gaps in what she can already do: edit an existing question or solution
line, move and reorder lines, repair a badly structured note without making duplicates,
and show you exactly what a removal would delete before asking to remove it. The rules
you already set stay enforced: one micro-step per line, stacked fractions and proper
powers and roots, the question preserved word for word, every question inside its own
real session, solution written before highlighting, highlighting before generating, and
she asks whether chips start in solution order or shuffled.

### Stage 3 — Pictures, video and a media library
A workspace media library holds every generated or uploaded asset with what made it, what
it may be used for, its size and length, a description for accessibility, and where it is
used. Aura can generate an original picture, revise it, preview it, save the approved one,
and attach it to a placement the game really supports.

Video is new work: script and storyboard, then a real generated clip with narration and
captions, run as a long job Aura polls. While it is running she says it is running. If it
fails she says so, keeps the draft, and offers the script. No voice cloning, no assuming a
link grants reuse.

Before any picture or video, Aura shows what it will cost and waits for your yes. Costs
are recorded per request so spending is visible and refusals are honest.

### Stage 4 — Rewards, honestly
Expose the real reward list and its real rules: Completion, Hourglass and Vault stay
derived from the question itself and are never placed by hand; hearts, bombs and
collectors are placeable. Aura can set the supported earning settings and conversions,
attach artwork, and preview appearance. Artwork is never treated as a reward. Marking stays
server-decided, and game results get a server-side write path so a reward cannot be
claimed twice or awarded without full marks.

### Stage 5 — Test, approve, publish
A hidden, clearly labelled test class with test learners in your own workspace. Aura runs
it there and returns inspectable results: the saved question references and their order,
how the mathematics renders, whether media loads and captions exist, timers and lives,
and whether a reward fired correctly and only once. Opening a preview never counts as a
pass, and preview activity is never recorded as achievement.

Publishing or assigning shows you the exact game, the exact classes and the cost, and
waits. Destructive changes and overwrites ask too. After publishing she re-reads it,
confirms it, and opens it for you.

### Stage 6 — Acceptance run, actually performed
The Indices game built from scratch on test records: questions, draft, rewards, one
original image, one captioned video, save, reopen, inspect, then approval. Plus the safety
run: a refused cross-workspace attempt, a repeated request that creates no duplicate, a
failed media job handled honestly, spending stopped at your limit, confirmation demanded
for deletion, and drafts invisible to students. I report what passed, what failed, and
what still needs your eyes.
