# Adventure becomes a reusable shell

Today a lesson note owns the adventure card: link one note to one progress bar, and that bar is then closed to everything else. The new model turns that around — the adventure is a finished experience you build once, the class is where you bring it in, and each progress bar collects whichever questions you send to it.

## What changes for you

1. **Class → Adventures** gets a **+ Link Adventure** button. You pick from the adventures you have already built. One class can hold several adventures, and the same adventure can be brought into as many classes as you like.
2. **Assign → Adventure** on a question now asks: which class, then which of that class's linked adventures, then which progress bar. If the class has no adventure linked yet, it says so and offers Link Adventure instead of inventing one.
3. **A progress bar collects questions.** Several questions from the same lesson note can go to different bars, and one bar can hold questions from different lesson notes. The same question may also sit on more than one bar — each is scored separately.
4. **Each bar is its own card.** Its questions, total marks, achieved marks, percentage, its own pass percentage and Pass / Not Passed are all calculated for that bar alone.
5. **Nothing leaks between classes.** Class B never sees Class A's questions, progress, or results on the same adventure. Unlinking an adventure from one class leaves the adventure and every other class untouched.

Your adventure editor — video, timeline, narration, effects, timers, rewards, progress bars — is not touched. Only the ownership and assignment side is rebuilt.

## Starting fresh

As you asked, existing note-to-bar links are cleared rather than converted. After the change you link each adventure to its class once, then assign questions to bars. Student work already recorded stays in the database as history; it just isn't shown under the old cards.
