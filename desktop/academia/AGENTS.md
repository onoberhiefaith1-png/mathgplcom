- The desktop Academia app (published as "Mathemagine" up to 1.0.1) is a thin Electron shell that starts at https://mathgpl.com/academia-app and relies on Academia's own offline worker and IndexedDB, so it never forks Academia code. Authoring routes under `/academia`, `/school/academia` and `/mcq/` stay inside the window so the in-app catalog can open a Session or View Questions; other links still open in the system browser. A manual Update (Home or Settings) unregisters the offline worker, drops HTML/JS Cache Storage, asks this shell over IPC (`mathgplDesktop.clearWebCache`) to clear the Chromium HTTP cache and service-worker registrations (never Cache Storage lesson media/packs, cookies, login, or IndexedDB), and reloads a cache-busted live URL. The JS path arrives by publishing the site; the IPC bridge and cache-busted first load require a new desktop installer (package.json 1.0.3). Do not bump `public/desktop/latest.json` until that installer is uploaded.
- Windows ships as a per-user NSIS installer (`installer.nsi`, built with nix `makensis` over `@electron/packager` output) because electron-builder fails in the sandbox; Mac ships as unsigned zips until Apple signing exists.
- User data lives in a fixed `Mathemagine` app-data folder (old profiles migrate once); that folder, the install folder `Programs\Mathemagine`, the uninstall key `Mathemagine` and AppUserModelId `com.mathgpl.mathemagine` keep the earlier name so upgrades replace the install in place; only visible names say Academia, so upgrades/reinstalls keep progress; the uninstaller keeps it by default.
- Shell updates are announced, never self-installed: the app compares its version to `public/desktop/latest.json`; bump that file, `package.json` and `src/lib/offline/releases.ts` together when re-uploading builds.
